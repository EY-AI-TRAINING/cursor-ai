End-to-End Ticket-to-Report
Engineering Copilot

The whole course in one run. Your team pulls a sandbox ticket it has never seen, and turns it into a requirement bundle, an approved plan, a spec note, a test sequence, executed PyTest cases, an independent review, green gates and a readiness decision. Then you tie it all together in one traceable engineering report a stakeholder can sign off without asking you a single question.

What’s actually new on Day 7?

Most of CA-1 … CA-10 already exist from Modules 16–19. The capstone adds two things:

  • An unseen ticket, end to end. The components are built. Today proves they compose on first contact with an unknown requirement, with open questions and all.
  • The report. One document that ties every artifact together so a stakeholder can decide from it.
The two human checkpoints (and no more)
🧑 Plan approval (CA-2)Before any code or tests are generated. It’s the cheapest checkpoint in the workflow: a wrong plan caught here saves the whole run.
🧑 HITL sign-off (CA-7)After the reviewer, bound to artifact hashes. Everything else is decided by code: gates, loop controller, CI, readiness policy.
About the example: your facilitator provides the real capstone ticket on Day 7. Its IDs, hashes, token counts and timings are made up for teaching. The artifacts, gates and policies follow Modules 16–19.

@pytest.mark.req("REQ-2517")
@pytest.mark.ac("AC-2")
@pytest.mark.seq("SEQ-3")
def test_change_address_shipped_order_rejected(api, customer_a, order_factory):
    order = order_factory(owner=customer_a, status="SHIPPED")
    r = api.as_(customer_a).patch(f"/orders/{order.id}/address", json=NEW_ADDRESS)
    assert r.status_code == 409
    assert r.json()["errorCode"] == "ORDER_LOCKED"      # round 2 fix: spec says ORDER_LOCKED, not ORDER_SHIPPED

@pytest.mark.req("REQ-2517")
@pytest.mark.ac("AC-2")
@pytest.mark.seq("SEQ-4")
@pytest.mark.xfail(strict=True, reason="DEF-5561: PACKED orders accept address change (200, spec requires 409)")
def test_change_address_packed_order_rejected(api, customer_a, order_factory):
    order = order_factory(owner=customer_a, status="PACKED")   # from the owner’s rev-5 clarification
    r = api.as_(customer_a).patch(f"/orders/{order.id}/address", json=NEW_ADDRESS)
    assert r.status_code == 409

    📌 Recap
    
One unseen ticket, one traceable package

    
    
      
  • Start from the ticket via a read-only MCP. Ticket text is data: owner-confirm LLM-split ACs, get open questions answered in the ticket, quarantine instructions.
    • 
      
  • Two human checkpoints: plan approval before generation, and hash-bound sign-off after review. Code decides everything else.
    • 
      
  • Spec ACs match the bundle one to one: the same IDs, the same meaning, the current revision.
    • 
      
  • Every test carries req and ac. Every failure is classed as test, product or environment. Product defects get a DEF-ID and a strict xfail, never a skip.
    • 
      
  • The reviewer runs in a separate context. Gates, the loop controller, CI and the readiness policy are code that the agents can’t change.
    • 
      
  • The report is compiled from evidence, lets anyone trace an AC in under a minute, and answers a stakeholder’s questions, including what it cost.
