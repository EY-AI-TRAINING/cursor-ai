§7 · Cloud/background agents: use cases, remote and test execution, PR-oriented workflows

Same agent loop, remote machine, output is a PR

A cloud agent clones the repo into an isolated VM, sets up the environment from a config file in the repo, works on its own branch, runs tests, and pushes. You review the result like any other PR. Nothing merges without required human review.

    📌 Recap

    From a laptop pipeline to a governed delivery path

    • Ticketing via MCP: sandbox project, scoped identity, read-only by default, writes behind a hook that asks, and deny if the hook fails.
    • Parse tickets into a schema-valid bundle with provenance. LLM-split ACs are claims for the owner to confirm, and ticket text is data, never instructions.
    • The ticket ID, AC-IDs and run ID go in the branch, trailers, PR title, test markers and report, and each convention is checked in CI.
    • CI re-verifies on a clean runner with least-privilege permissions. AI reviewers advise; people approve and merge.
    • Readiness is a versioned policy over CI, gates, sign-off, coverage, defects and security, and anything that can't be evaluated means NOT READY. A person still approves the environment.
    • Cloud agents return PRs, never deployments. Before delegating, check environment, secrets, network, permissions and human review.
