01 / Topology

Sequential vs. parallel pipelines

A sequential pipeline runs one stage at a time, and each stage waits for the one before it. A parallel pipeline splits independent work across agents and adds a merge step at the end. Run both and compare wall-clock time with total agent time.

03 / Delegation

Subagents and independent context

A subagent starts with an empty context window. It gets a brief, does the messy work (searching, reading, trying things), and returns only a short result. The parent's context stays small, so it keeps following its original instructions.

  • A summary or artifact, not a transcript
  • Evidence: file paths and line numbers
  • Status: done, blocked, or needs input

Because the subagent can't read the parent's conversation, a vague brief like "fix it like we discussed" won't work. The brief has to stand on its own.

04 / Resilience

Failures, retries, timeouts, and bounded execution

Every stage will fail at some point. What matters is whether the pipeline recovers, stops safely, or hangs and burns budget. Pick a failure, set a policy, and run the API Validator stage.

Cheat sheet · match the policy to the failure
FailureRetry?HowWhen retries run out
Transient (503, rate limit)yesBack off: wait longer before each tryEscalate and halt downstream stages
Hang or slow toolyesAlways set a timeout per attemptMark the stage timed out, keep partial logs
Bad output (schema, failing tests)with feedbackInclude the validator's error in the next promptHand off to a human along with the last attempt
Permanent (401, missing file, bad spec)noFail fast: retrying won't change the resultStop right away and say what needs fixing

Bounded execution means every run has a limit: max attempts per stage, max steps or tool calls per agent, max wall-clock time, and max spend. A pipeline with no limits can loop forever.

05 / Granularity

How many agents is too many?

Each extra agent adds specialization, but it also adds a handoff, a new way to fail, and more tokens. Past a certain point, coordinating the agents costs more than the specialization gains. Drag the dial to find that point.

Specialization benefit Coordination overhead Net value
Decision helper · what does this task need?
🪆 Agent per functionIf an agent only renames variables, it should be a step inside another agent, or a rule.
🔁 Reviewer reviews the reviewerAdding layers of checks makes each layer less accountable. Use one independent reviewer, then a human.
🕸️ Everyone talks to everyoneA mesh of agents is very hard to trace. Stick to a pipeline or a single fan-out with one merge step.

📌 Recap

Write the score before you hire the orchestra

  • Use a sequential pipeline when each stage needs the previous stage's output. Fan out in parallel only when branches are independent, and plan a merge step.
  • Agents share state through an explicit handoff artifact, not shared memory. Each stage adds its own keys to it.
  • Give every role a contract: its input, output, allowed tools, what it must not do, and its PASS/FAIL signal.
  • Subagents start with a fresh context. Give them a brief that stands on its own, and have them return a summary, not a transcript.
  • Retry transient errors with backoff, retry bad output with the error included, and fail fast on permanent errors. Set a limit on every run.
  • Use the smallest number of agents that does the job. One trace_id across all handoffs is what lets you debug and audit the run.
