05 / Creating reusable prompt templates and standard workflows

Turn a good prompt into a repeatable one

A good one-off prompt is a lucky draft. A template is a team default.

One-off prompt
Can you write a PR description for the changes I just made, explaining what changed and why, and format it for our team?

Quality depends entirely on whoever happens to be typing that day.

# .cursor/prompts/pr-description.md
## Summary
{{summary}}
 
## Why
{{motivation}}
 
## Testing
{{testing_notes}}
 
## Risk
{{risk_level}} — {{risk_notes}}

Same shape and quality every time, for anyone who runs it.

Standard workflows chain templates like this together — plan → implement → test → PR description — each step reusing a known-good template instead of a fresh, improvised prompt.

07 / Subtopic: version-controlling rules and skills; keeping instructions concise, testable, and maintainable

Treat instructions like code — because they are

A vague rule is worse than no rule. Here's the same instruction, before and after.

✗ Not testable

"Write good tests."

Vague — nobody can tell whether it was followed or violated.

✓ Testable

"Every new API endpoint needs a request-validation test and a 4xx-response test, colocated in the same folder."

Specific — you can check whether it happened.

Committed and reviewed like any other change:
# .cursor/rules/testing.mdc
- Write good tests.
+ Every new API endpoint needs a request-validation test and a 4xx-response test, colocated in the same folder.
# reviewed and merged like any other pull request

📌 Recap

Day 2, complete

  • Project Rules in .cursor/rules/ scope AI instructions to specific files or the whole repo, and travel with the codebase instead of living in someone's head.
  • AGENTS.md is a portable, plain-text convention for persistent repo guidance that multiple AI tools can read.
