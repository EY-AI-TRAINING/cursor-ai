01 — What crosses the boundary

Every connected source is also a data exposure

Connecting a document store or knowledge base means whatever's inside it can end up inside a prompt, a log, or a model call. Data privacy and IP handling decide what's allowed to make that trip before a connection is approved — not after something leaks.

02 — Who can grant what

Admin controls decide who can turn on agent tool access

Access to repositories, MCP connections, and tool execution isn't a per-developer setting in an enterprise rollout — it's granted by admins, scoped per team or project, and every grant and every use gets written to an audit log.

03 — Four layers between an agent and damage

Safe execution stacks four independent controls

Controlled tool access limits which tools exist at all. Permissions limit which actions are reachable. Sandboxing contains what a wrong action can touch. Approvals gate the moment right before a risky action runs. Any one layer failing shouldn't be catastrophic.

04 — The rules don't pause for AI

SOC2 and GDPR apply to what the agent touches

A grounded agent reading personal data out of a defect log or a customer ticket triggers the same GDPR obligations a person reading it would. SOC2's access-control and audit expectations apply just as directly to an agent's tool calls as to a person's.

05 — See the whole pipeline, not one call

A trace follows a task across every agent that touched it

Once multiple agents hand work to each other — as in Module 11's library, and later Module 16's chained pipeline — a log line per call isn't enough. Tracing threads one task through every agent, tool call, and handoff it passes through as a single connected timeline.

06 — What to actually capture

A useful handoff log is specific, not just present

Logging "agent ran" tells you nothing when something breaks. A useful handoff log captures what was received, what it was grounded against, what it produced, and whether a guardrail fired — the same fields, every time, at every handoff.

07 — Know what a task costs before it scales

Cost visibility turns "it's cheap" into a number

Every agent call spends tokens, and every task is made of several calls. Without per-call and per-task visibility, a workflow that looks free in a demo can become the most expensive line item once it's running across a whole team, every day.

08 — Subtopic: the policy layer underneath it all

Four policy decisions every rollout makes once

Which knowledge sources are approved vs. restricted, which files and folders are off-limits regardless of who's asking, how secrets stay out of context entirely, and which observability tooling actually surfaces these logs — decided once, centrally, not re-litigated per agent.

09 — Hands-on exercise and quiz

Configure one policy, then trace what it produces

A short, focused exercise to close Day 4: set one access-scoping policy, run a sample multi-step task through it, and read the trace and handoff logs it generates. A short quiz checks the governance vocabulary from this module before Day 5 begins.
