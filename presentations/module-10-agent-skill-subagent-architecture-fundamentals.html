01 — Five overlapping terms

Not synonyms — a spectrum of autonomy

Rule, prompt, skill, agent, and subagent all "give the AI instructions," which is why they get confused. The real difference is how much autonomy each one holds — from a passive, always-on constraint to a fully delegated unit of work with its own isolated context.

02 — Reusable agent design

Four inputs define what an agent can and can't do

A reusable agent isn't just a system prompt — it's a role, a defined set of inputs, an explicit toolset, and guardrails that bound its behavior, all producing a consistent kind of output. Skip any one of the four and the agent becomes unpredictable to reuse.

03 — Focused, isolated, handed back

A subagent sees the task, not the whole conversation

Delegating to a subagent means handing off a focused unit of work with its own isolated context — it doesn't inherit the parent's full history, and it doesn't hand back its raw working context either. Only the result crosses the boundary.

04 — Explicit contracts, not prose

Same template, different run, same shape back

A parameterized prompt template defines its input slots and its output shape once — explicit enough that the result can be checked mechanically, not just read. Every instantiation fills the same contract with different concrete values.

05 — Scope of reuse

One repo's rules vs. every repo's skills

Repository-level rules stay local — they shape how agents behave inside this one codebase. A team-level skills library lives outside any single repo, versioned on its own, and gets pulled into many repositories at once.

06 — Composition, not a new engine

Reusable workflows are built from parts you already have

Designing a reusable workflow means composing rules, skills, agents, and subagents Cursor already supports natively — reaching for external glue like MCP, Git, or CI scripts only where the task genuinely needs to cross outside the IDE.

07 — Subtopic: treat definitions like code

Review every definition — and question every split

Agent and skill definitions get versioned and reviewed exactly like the code they operate on. And before splitting one agent into three, the question is always whether the extra handoffs buy more than they cost — unnecessary decomposition is its own kind of technical debt.
