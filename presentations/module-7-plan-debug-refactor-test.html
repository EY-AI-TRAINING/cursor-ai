01 — Structured thinking

Four steps before the first edit

Plan mode is for tasks too big to trust to a single prompt. It explores the codebase, drafts a step-by-step plan, and stops — nothing gets implemented until you've reviewed the plan itself, not just the eventual diff.

02 — Method, not guessing

A failure is a hypothesis to test

Debug mode doesn't jump straight to a fix. It observes the actual failure, forms a specific hypothesis about the cause, and tests that hypothesis before touching any code — refining and re-testing until the root cause is confirmed.

03 — Restructuring

Same behavior, untangled structure

A plain-language instruction can restructure legacy code — pulling a dense, tightly coupled function apart into small, independent pieces — without changing what it does. The shape of the code changes; the shape of the connections between its pieces changes with it.

04 — Diagnosis

From a wall of red text to a specific line

A stack trace buries the one frame that matters inside a dozen that don't. AI reads the whole trace, points at the actual root-cause line, explains it in plain language, and proposes a fix scoped to exactly that line.

05 — Verification

Tests close the loop the debugger opened

AI drafts a test straight from the function, runs it, and reads the result. A pass ships with confidence; a failure feeds its own output back in as the context for the next attempt, the same failure-as-context habit from Module 6.

06 — Subtopic: the safety net

Tests are the safety net for everything above

Refactoring is only safe to trust when the existing suite is green before and green after. When a test does fail mid-refactor, its output — not a fresh guess — becomes the context for the next attempt.

07 — Hands-on

Exercise, then a quick check

Module 7 closes with practice across the full loop — plan, debug, refactor, test — then a knowledge check before Module 8 turns to making these habits durable across a team.

Part 1 — Exercise

Debug, then refactor, then prove it

Use Debug mode to isolate the cause of a failing test, apply a natural-language refactor to the surrounding function, and confirm the full suite is still green before considering it done.

Part 2 — Quiz

Knowledge check

Short quiz on Plan mode's four stages, recognizing a confirmed vs. unconfirmed hypothesis, and finding the actual root-cause frame in a stack trace.
