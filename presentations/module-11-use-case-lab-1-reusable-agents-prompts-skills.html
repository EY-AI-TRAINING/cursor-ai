01 — Four independent roles

Define the roles before you chain anything

Requirement analysis, test generation, validation, and documentation each get their own agent role, defined and tested on their own. They stay independent here — orchestrating them into a sequential pipeline is Use Case Lab 3 (Module 16), not this lab.

02 — Enforced, not just described

A contract a call can fail

An explicit input/output contract means a call either conforms or it doesn't — checkable mechanically, not just readable. Two calls pass because their inputs and outputs match the declared schema; one fails because a required output field is missing.

03 — Package once, share everywhere

From working files to a versioned library

The four agents, their templates, and the rules that scope them get packaged into one structure and committed — the same discipline Module 10 introduced, now producing an artifact the whole team can pull into their own repos.

04 — One focused delegation

Carve out one task the parent agent shouldn't do itself

Not every task belongs in the main agent's context. Here, the Documentation Agent delegates one narrow, independent task — summarizing an API surface — to a subagent that works in isolation and hands back only the finished summary.

05 — Prove it before you connect it

Every asset earns its place on its own evidence

Before anything gets chained together in a later lab, each of the four agents and the new subagent runs once against a sample input on its own — independent proof it behaves as defined, not just a hope that it will.

06 — What ships from this lab

A library, not a demo

The deliverable is the committed library itself — four tested agent roles, their prompt templates and contracts, the packaging rules, and one focused subagent — ready for Module 13's Use Case Lab 2 to connect to a knowledge source.

Deliverable · Feeds Module 13

shared-library — committed to the training repository

4 agent role definitions (requirement analysis, test generation, validation, documentation) · parameterized prompt templates with input/output contracts · packaging rules and skills · 1 focused subagent · independent pass/fail evidence for every asset — tagged and version-controlled, not left in a single chat.

07 — Hands-on lab and peer review

Another team checks the library before it counts as done

The lab isn't finished at commit — a peer team reviews the library against the same bar Module 10 set: is each role clear, is the contract explicit, are guardrails present, and is there real independent test evidence for every asset.
