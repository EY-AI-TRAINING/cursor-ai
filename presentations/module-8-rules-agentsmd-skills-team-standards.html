01 — Scoped instructions

Instructions that only apply when they're relevant

Project Rules live in .cursor/rules/ as small files, each scoped to a glob pattern — or marked "always." Only the rules matching the files actually in play get pulled into context; the rest stay silent.

02 — Universal guidance

One persistent file every agent reads

AGENTS.md takes the opposite shape from Rules: not many files scoped by glob, but a single file at the repo root, written once and read by any agent that opens the project — Cursor or otherwise.

03 — Conflict resolution

When instructions conflict, project wins

Instructions can exist at three levels — personal, team, and project. They're layered, not merged blindly: the most specific scope, the project itself, takes precedence over team conventions, which in turn override a user's personal defaults.

04 — On-demand expertise

Specialized capability, invoked on demand

Skills package a specific capability — commit-message conventions, a review checklist, a document format — that stays out of context until a request actually matches it. Only the matching skill gets pulled in; the rest of the deck stays untouched.

05 — Reusable structure

One template, consistent every time

A prompt template defines the slots once — summary, changes, test plan — and every use fills the same shape with different content, instead of re-explaining the structure from scratch each time.

06 — Team-wide adoption

From individual habits to one shared standard

Left alone, every engineer develops their own ad-hoc prompting style — inconsistent, unreviewed, invisible to teammates. Standardizing means routing all of it through one versioned source: shared rules, shared skills, shared templates.

07 — Subtopic: treat it like code

Rules and skills live in git too

A rule or skill change is a commit like any other — reviewed in a pull request, held to the same bar: concise enough to read in one pass, testable against real examples, and maintainable as the project changes.

08 — Hands-on

Write the rules your future agents will follow

Module 8 closes with a single hands-on exercise — no quiz. What you build here isn't just practice: it's the direct foundation for Module 9's spec-driven design work and Module 11's reusable agents lab on Day 3.

Exercise · Feeds Module 9 & Module 11

Draft a rules-and-skills starter kit

Write one scoped Project Rule, a short AGENTS.md for the sample repo, and one reusable Skill, then commit all three like any other change. Keep each one small enough to read in a single pass — you'll build directly on this starter kit in Module 9 and again in Module 11's Use Case Lab.

09 — Before Day 3

Carry these four ideas forward

01

Project Rules are scoped by file and Cursor-specific; AGENTS.md is universal and read by any agent.

03
