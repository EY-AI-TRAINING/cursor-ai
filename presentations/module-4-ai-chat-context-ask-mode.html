AI Chat, Context & Ask Mode

01 — Scope

Same question, three different scopes

AI Chat answers from whatever scope you hand it — a single open file, a chosen folder, or the whole indexed codebase. Scope isn't a setting you pick once; it's the single biggest lever on whether the answer is generic or exactly right for your repo.

02 — Precision

@ turns "somewhere in the repo" into an address

Typing @ opens a picker for files, folders, docs, symbols, and the codebase index itself. Each mention resolves to something concrete before the model ever sees your message — not a vague pointer, but an actual file, an actual function, an actual document, attached to the prompt.

03 — Boundaries

One reads, the other acts

Ask mode is a conversation: it reads code, explains it, and answers questions, but it never touches your files or your terminal. Agent mode is a worker: it proposes edits across multiple files and can run terminal commands — but every one of those actions still waits on your review, per Module 1's verification gate.

Ask / Chat mode

  • ✓ Read & explain code
  • ✓ Answer questions about the repo
  • ✗ Edit files
  • ✗ Run terminal commands
  • ✗ Multi-file changes

Zero blast radius — the worst outcome is a wrong sentence, not a wrong file.

Agent mode

  • ✓ Read & explain code
  • ✓ Propose multi-file edits
  • ✓ Run terminal commands (scoped)
  • ✓ Run a plan → act → verify loop
  • ✗ Ship without your approval

Real blast radius — which is exactly why every diff still waits for you to say yes.

04 — The goldilocks curve

More context isn't automatically better

Too little context and the model guesses. Too much — an entire monorepo dumped in because @-mentioning felt like extra work — and the one relevant file gets buried in noise it has to sift through. Reliability peaks in the middle: specific, relevant, deliberately scoped.

05 — Maintenance

A long chat is still bounded

Every turn in a conversation stays in context for the next one — until the window fills, exactly as in Module 1. Two honest ways to keep going: start a new chat and lose the thread entirely, or summarize the old turns into a short block and carry the thread forward at a fraction of the cost.

06 — Subtopic: analysis prompts

A reliable answer is a small equation

For analysis tasks specifically — "explain this," "find the bug," "compare these approaches" — three ingredients combine into a first-try answer: one specific question, context sized to exactly what it needs via @-mentions, and a constraint on what shape the answer should take.

07 — Hands-on

Exercise, then a quick check

Module 4 closes with practice, not a lecture: put scope and mentions to work, then confirm the concepts stuck before Day 1 moves into hands-on coding tomorrow.

Part 1 — Exercise

Same question, three scopes

Ask the identical question with File, then Folder, then Codebase scope, and compare the three answers side by side. Then repeat it once more using explicit @-mentions and see which answer it matches.

Part 2 — Quiz

Knowledge check

Short quiz on Ask vs. Agent mode boundaries, @-mention syntax, and recognizing a context-limit warning before it silently truncates your history.

08 — Before Day 2

Carry these four ideas forward

01

Scope — file, folder, or codebase — is the single biggest lever on chat answer quality.

02

@-mentions turn a vague pointer into an exact file, symbol, or document before generation starts.

03

Ask mode reads and explains; Agent mode proposes and executes — know which one you're in.

04

Reliability peaks at targeted context and drops on both sides — too little, and too much.
