Module 13 — 90 minutes, the second Use Case Lab. Module 12 supplied the mechanics: grounding sources, MCP, retrieval strategies, and a guardrail against unsupported facts. 01 — Wire up the sources

Connect through MCP, not ad hoc scripts

The repository stays in direct context — no protocol needed for what's already local. Everything that lives outside the repo — the document store, the defect database, the enterprise knowledge base — connects through the MCP server built out in Module 12.

02 — Scope the pull, cite the pull

Every retrieval is scoped, every answer is cited

Scoping decides which paths, collections, and time ranges a retrieval is even allowed to search. Citation is the other half of the same discipline — every factual sentence in a response carries a pointer back to exactly where it came from.

03 — Constrain it the same way as Module 8

Rules set the boundary the MCP config alone can't

Connecting a source doesn't force an agent to behave — a project rule does. The same `.cursor/rules/` mechanism from Module 8 pins down citation format, refusal wording, and which sources are even in play, as reviewable, version-controlled text.

04 — Prove the refusal works

An out-of-scope question is the real test

A grounded agent isn't proven by the questions it answers well — it's proven by what happens when the answer isn't there. Three questions, three outcomes: answered and cited, answered with a caveat, and correctly declined.

05 — What ships from this lab

An agent that cites sources and declines the rest

The deliverable is the whole configured system: the MCP connections, the retrieval-scope config, the enforcing rule, and evidence from the stress test — committed alongside Module 11's agent library in the shared training repository.

grounded-agent — committed to the training repository

06 — Hands-on lab and peer review

Another team tries to break the grounding before it counts as done

As in Module 11, the lab isn't finished at commit. A peer team reviews the grounded agent against its own bar: is scoping correct, is every claim cited, and does it actually refuse instead of guessing when pushed.

07 — Before governance

Carry these four ideas forward

01

The agent reaches real sources through MCP — repo code stays direct context, everything external goes through the protocol.

02

Retrieval is scoped by config, and every factual claim in a response carries a citation back to a specific source.

03

A project rule enforces citation and refusal behavior — connecting a source doesn't by itself force good behavior.

04

The real proof is the stress test: out-of-scope questions were correctly declined, and a peer verified it before merge.
